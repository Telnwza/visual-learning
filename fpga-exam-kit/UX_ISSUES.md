## User feedback

- The program feels bloated, with too many screens and confirmation steps.
- Importing and using a module does not match the expected ordinary module workflow.
- The user wants deliberate UX work and tighter scope, rather than accumulating quick fixes and extra features.
- Preserve independent judgment: investigate which interactions are actually unnecessary rather than assuming every feature should be removed.
- Latest direction: this is a personal tool. Remove unnecessary teaching, reassurance and repeated explanatory copy from the working UI; keep concise labels, actionable errors and actual consequences. Do not replace the deleted text with more explanations.

## Tasks and completion boundaries

| Task | Intended completion | What the audit distinguishes |
|---|---|---|
| T1 — Bring in modules | Valid modules are available, findable and usable as boxes; dependencies are resolved. | Import success is not placement or a working circuit. A single-file import and a 49-file import have different discovery needs. |
| T2 — Configure and place | A box has the intended generic values at a user-chosen location; valid existing connections are preserved. | An instance's generics differ from the shared module definition/source. Visual size differs from electrical width. |
| T3 — Wire and adjust | Matching pins connect; consequential interface changes are explained; Undo/Redo restores the operation. | Ordinary wiring already works without a confirmation and should be preserved. A connected-width change has consequences even if no wire is deleted. |
| T4 — Check and export | The downloaded code matches the current top and reachable dependencies, with truthful validation status. | Studio structural checks, generated VHDL, compiler success and physical hardware validation are separate evidence. |

## Feedback and recovery rules to evaluate

These are proposed behavior contracts, not blanket rules to delete dialogs.

| Situation / state | Feedback and commitment | Recovery boundary |
|---|---|---|
| Import reading/validating | Brief inline pending state at the import entry; no old green “ready” result while a new batch is being read. | Preserve selected files; cancel has no commit. |
| Valid new import | Visible new module(s), concise completion count, one project transaction. | One Undo removes the imported batch. Placement remains separate. |
| Missing dependency / conflicting source | Persistent specific error with the missing name/conflict and a correction action. | Retain the pending batch; do not partially install unrelated items or silently replace existing source. |
| Choosing/placing a component | Pointer/canvas draft or direct drag feedback; no success modal. | Esc cancels before placement; one Undo removes a committed part. |
| Instance setting with no connected interface/data loss | Inline validation and visible committed value; no blocking confirmation. | Reject invalid values without losing the last valid value; keep keyboard focus and Undo. |
| Connected width/direction change | One Inspector summary naming affected endpoints and pending values, then deliberate Apply/Cancel. | Preserve original until Apply; one Undo restores settings and wires. |
| Port removal with connected wires, CONST truncation, or removal of a used definition | One concrete warning before commitment, including counts/values that will be lost; no second generic “Are you sure?” dialog. | Cancel preserves everything; Undo must restore the complete operation where supported. |
| Shared source update | One explicit Update action showing definition/instance scope and interface consequences. | Validation failure retains draft; no partial replacement; Cancel/Undo are well-defined. |
| Visual resize | Live canvas result and ordinary selection/size feedback. | Esc cancels an active drag; one Undo restores geometry/routes. |
| Check / Generate / Export | Truthful local-check status, preview freshness and exact download scope. | A generation failure leaves the current project intact and does not report a new valid download. |

Physical file pickers/Save dialogs are required system interactions, not something to eliminate categorically. Likewise, removing a destructive guard is not justified merely because Undo exists; restoration must actually include affected definitions, instances, values and wires.

## What the evidence does not justify removing

- Normal matching-width wiring: the browser connected PIPO q[8] to a new OUT[8] with two port clicks and no dialog. The visible wire count changed 8→9; Undo returned 9→8 and Redo restored 8→9.
- Meaningful interface-impact calculation: changing the connected PIPO WIDTH 8→9 correctly identified `ss_reg_pipo.q → out0.i` as one affected wire. The proposed change concerns where/how often that consequence is shown, not suppressing it.
- Generic configurability, 1–64-bit data, enable, source preservation, real clock/reset semantics, multi-wire helpers, layout locking, saved-project compatibility and imported sources. No evidence here authorizes removing their functionality.
- Other workbenches, legacy HTML files or the separate Top-down concept. File count alone does not establish unused product scope.

### ลำดับแก้และหลักฐาน

ปรับแผนเดิมห้าช่วง ไม่เพิ่มเฟสใหม่: UX-A รวม export/check, การต่อสายก่อนแทน driver, Inspector ที่ตรงกับ selection และผลการลบพอร์ตข้ามแผ่น ให้แก้ก่อนงานจัดหน้าตา; UX-B เพิ่ม label พอร์ตกับ controls ตามบริบท; UX-C คงงาน import; UX-D เพิ่มการหยิบ SCH/CUSTOM แบบเดียวกับ primitive และจำมุมมอง; UX-E ตรวจ flow เหล่านี้ผ่าน UI จริง

- [Probe ฟังก์ชันจริง](../output/ux-audit-2026-10-18/probes.json): สายเดิม data[8] เปลี่ยนเป็น clk[1] หลังต่อผิด, multi-wire ปฏิเสธโดย state ไม่เปลี่ยน, Undo คืน state เดิม และ Check รายงานแผ่นที่อยู่นอก bundle
- [Selection เทียบ Inspector](../output/ux-audit-2026-10-18/selection-inspector.json) และ [ภาพหน้าจอ](../output/ux-audit-2026-10-18/selection-inspector-stale.png): DOM ที่วาดเลือก c47/c48 แต่ panel ระบุ c47 กับพิกัดเก่า
- [ผล Check หลังต่อผิดขนาด](../output/ux-audit-2026-10-18/wiring-width-errors.png) และ [parent หลังลบพอร์ต child](../output/ux-audit-2026-10-18/parent-after-port-delete.png) เป็นภาพโปรแกรมปัจจุบัน ไม่ใช่ภาพแบบหน้าตาใหม่
- การเริ่มแผ่นด้วย `New schematic` ทดสอบไม่จบใน in-app browser นี้ เพราะ runtime แจ้ง `prompt() is not supported` จึงสร้าง fixture ผ่าน Schematic Text แทน ไม่จัดข้อจำกัดนี้เป็น bug ของโปรแกรมบน browser อื่น
- ตรวจใน local working tree ไม่ได้เปรียบเทียบ deployment ไม่ได้วัดเวลาผู้ใช้ ไม่ได้ตรวจ native file picker, clipboard Paste ข้ามแผ่น, port reorder ทุกกรณี, keyboard placement, GHDL/Vivado หรือบอร์ดในรอบนี้
- รอบนี้แก้เอกสารแผน/ปัญหาและบันทึกหลักฐานเท่านั้น ตรวจ checksum ของตัวโปรแกรมกับ module artifacts เทียบก่อน audit อีกครั้งก่อนส่งมอบ
